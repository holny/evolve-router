# 心选模型候选范围（Favorite-Model Routing Scope）— 设计

- 日期：2026-10-28
- 状态：待批准（brainstorm 已完成，标签样式与挑选交互均已由用户在 mockup 上选定）
- 参与决策：用户（全部关键裁决）+ BocomCode（整理）

## 背景与动机

目录 700+ 模型，多数不是用户需要的或性价比不高，网关自动选路会"误启用消费"。现有组合
（portfolio：每 provider 名额 + 9 格覆盖 + 免费直通车）的填充是纯自动逻辑（发布/近用），
用户无法主导。用户期望：**主要依靠用户自己的判断**（用户对"哪家哪个模型强"有外部认知），
网关提供一个小而准、可动态调整的候选范围；同时零配置也能照常跑。

## 目标 / 非目标 / 反目标

### 目标
1. 每 provider 候选范围 = **3 心选位 + 2 昨日用量位 + 1 最新位 + 全部免费模型**（去重后为实际成员）。
2. "能力×价位" 9 格**尽量填满、不允许空格**：范围成员跨格代表（相邻格放宽门槛），盖不住的格由
   该 provider 其余模型按公式分以 REC（推荐）身份补入。
3. 心选模型有优先级加成（默认较高档，用户可用现有 ▲▼ 任意调整——不重复造机制）。
4. 档位带距从"加性 +100/档 碾压"改为**乘法加成**（±30% / ±60%，+3 必选 / -3 禁掉）。
5. 一天用量的期望分布（心选+免费 ≈70%、免费占其中大头；昨日量 ≈10% 用作挽救起量补数据；
   最新 ≈20% 看效果）是**涌现效果**——靠打分规则实现类似效果，**不做编程硬限制**。
6. macOS 面板 + Web：来源标签（英文、彩色淡底描边胶囊）、Favorites 卡 + 比较选择器、
   被动引导横幅；未选心选时默认照跑（引导不是必须步骤）。
7. **双路径架构**（用户裁决 2026-10-28）：现有自动路由保留为 **Gateway（网关智能）** 路径，
   本设计为 **Favorites（心选智能）** 路径；全局模式开关**热切换**（不重启网关），托盘与
   Web 双入口同源；默认 Gateway，升级用户行为不变。

### 非目标
- 不做配额/掷骰子式硬分流。
- 不做自动心选推断（用户自己挑；默认链兜底）。
- 不新增存储后端（复用 overrides.json / flywheel 小时桶 / events 日志）。
- 不改粘性、价位闸、探索等既有机制语义（档位带距除外）。

### 反目标（出现即失败）
- 弱免费模型在难题上赢过心选强模型（质量下限对非 +3 档仍必须生效）。
- 范围小到某 provider 的难题无模型可用（REC 兜底必须防住）。
- 未选心选时路由变差或不可用。

## 约束

- 复用既有设施：优先级 7 档 ▲▼ 双入口（`/api/priority` + overrides.json）、tags 系统
  （`/api/model-tags` 两端同源渲染）、flywheel 持久化小时桶（日历窗口取数）、9 格矩阵、
  events 日志、Pinned 唯一性降档规则。
- MenuBarExtra 面板：`.help()` tooltip 不触发；面板宽度窄。
- 对外标签一律英文；Web dashboard 走 i18n 词典（en 为主文案）。
- 既有工程纪律：Swift 具名参数新字段追加到结构体末尾；axum layer 必须在路由注册之后；
  f64 域做取整等（见项目记忆）。

## 方案（已定）

### 1. 心选路径的候选范围选择（新增路径；Gateway 路径保留现有组合算法）

每家健康 provider（可路由、无结构性不可用）：

| 位 | 数量 | 选举规则 |
|---|---|---|
| FAV 心选 | ≤3 | 用户挑选；空位按链回退：昨日用量最高 → 最新入库 |
| TOP 昨日 | 2 | 日历"昨天"token 用量降序前 2 |
| NEW 最新 | 1 | 目录内 release_ts 最新（provider `/models` created → models.dev → id 内嵌日期链） |
| FREE 免费 | 全部 | 直通车，不占位（沿用现裁决） |

- 各角色位独立选举后**去重**，范围大小 = 去重成员数（最少 ≈3，通常 4-6 + 免费）。
- **9 格覆盖**：范围成员可跨格代表（能力相邻 ±1、价位相邻 ±1 视为可代表，门槛放宽）；
  某格无任何范围成员 → 该 provider 目录其余模型中**稳定口径分**最高者以 REC 身份入范围
  （bench 能力档 × 用户权重 × 价位效率；不含随时间漂移的实时可靠性/速度遥测——避免兜底
  兜到"今天恰好抖动"的模型）。**格不允许空着**（用户明确纠正：尽量填满）。
- 范围成员仍受一切硬闸约束（健康冷却、配额闸、上下文窗口、视觉、价位闸）——范围 ≠ 豁免。
- 接入点：新增 `favorite_scope_selection`（即本规则）；**Gateway 路径的
  `portfolio_selection` 原样保留**；`routing_mode`（overrides.json 持久化，热切换）决定
  `active_id_set` → `RoutingInput.active` 的数据源走哪条路径；用户 Off(-3) 排除两路通用；
  **旧 enable/disable 开关退役**（见下条）。
- **退役旧 enable/disable**（用户裁决 2026-10-28）：新范围没有全局名额，"启用顶掉最低分"
  失去意义；"排除"与 Off(-3) 重复、"强制启用"与 +3 Pinned/心选重复。
  `overrides.active_models.include/exclude`、`/api/models/active` 及 Dashboard/托盘对应
  UI 与文案一并下线。排除只用 Off(-3)，强制只用 +3 Pinned 与心选。
- 来源标签唯一性：每模型一个主来源标签，优先级 FAV > TOP > NEW > REC；FREE 为第二标签叠加
  （免费的 FAV 模型显示 FAV + FREE）。

### 2. 打分与档位（涌现 70/10/20）

- **档位带距改造（两条路径共用，用户裁决 2026-10-28）**：`PRIORITY_BAND_STEP=100` 的加性带距 → 乘法加成作用于总分：
  0 档 ×1.00；+1 ×1.30 / -1 ×0.70；+2 ×1.60 / -2 ×0.40；**+3 = 必选**（入池豁免质量下限与
  范围过滤；保留 Pinned 每 provider 唯一、旧 Pinned 自动降 +2）；**-3 = 禁掉**（= 现 Off，
  全链排除，sweep 兜底亦不可捞回）。
- **行为变化**：+1/+2 不再豁免质量下限（只有 +3 豁免）——难题上未心选的强模型可凭公式分
  赢过加成后的弱心选；质量底线继续保护未被抬高的路由。
- **心选默认加成**（用户裁决：只做软偏好；**仅 Favorites 路径生效**——Gateway 路径的
  用户偏好通过显式 ▲▼ 档位表达）：FAV 未被显式调档时在**路由总分上乘 ×1.30**
  ——仅作用于打分竞争，**不改变粘性接管、低置信留旧、缓存经济等读档位的比较点**
  （否则设心选即打断全部粘性会话）。显式 ▲▼ 调档仍走完整档位语义（含接管粘性）。
  不落盘、不与优先级存储耦合；取消心选自动回落（幽灵残留为零）。
- **NEW 新手保护（仅 Favorites 路径）**：×(1 + 0.40 × decay)，decay 随该模型累计完成 token 线性衰减
  （首 50K token 衰减到 0，参数可配置）——新模型自动获得一段试验流量，跑不出效果自然沉底。
- **TOP / REC**：不加成（范围本身小就是份额机制；TOP 的"挽救起量"由范围资格保证）。
- **FREE**：不加成（cost 项已把免费成本分拉满，"免费占 70% 里的大头"由 cost 权重涌现；
  难题/价位闸自然过滤弱免费）。
- **配比验证**：events 记录每请求选中模型的来源标签 → 新增"来源分布"统计视图
  （面板卡 + web 卡），实际观察涌现效果，偏离就调加成数字，不写限额。

### 3. 数据与 API

- overrides.json 增 `favorites: { provider: [model_id, …] }`（服务端强制 ≤3，幽灵 id 拒绝，
  与 priority 的防御一致）。
- `GET/PUT /api/routing-mode`：读/设 `gateway | favorites`（overrides.json 持久化，
  热切换不重启；切换不打断进行中的粘性会话——跑完自然结束，下一个新决策起用新模式）。
- `GET/POST /api/models/favorite`：GET 列某 provider 目录全量 + 当前心选（选择器数据源）；
  POST **槽位语义** `{provider, model, replace?}`——增设第 4 个必须指名替换谁（UI 的
  "点行即换选"流程天然带 replace），服务端不做"拒绝后让用户猜"；幽灵 id 拒绝
  （与 priority 的防御一致）。
- `/api/model-tags` 增 `source` 字段（fav/top/new/rec/none）；`free` 已有。
- 昨日用量：flywheel 持久化小时桶按日历"昨天"窗口聚合 token，**口径 = 输入+输出合计**
  （沿用 api_stats 的 absolute-window 机制），按 provider+model 出列；首日 TOP 数据不足时
  空位由 NEW 顺位补第二个不同新模型（不空格原则）。
- 上线首日昨天无数据：TOP 位空 → 由 NEW 兜底（用户原话：昨天没量用新增代替），随后自然恢复。

### 4. UI（mockup 已选定）

- **模式开关**（mockup 已选 B：头行内嵌紧凑开关，贴标题右侧，零额外高度）：
  两段切换 `Gateway | Favorites`（Web dashboard 头部同款）；
  写同一 `/api/routing-mode`。Gateway 模式下面板维持现状（隐藏收藏卡、来源标签、
  来源分布卡）；Favorites 模式显示收藏卡 + 来源标签 + 来源分布。英文段位文案
  `Gateway` / `Favorites`，web i18n 对应 网关智能 / 心选智能。
- **来源标签**：淡底描边胶囊（与现有 capability/price 胶囊同语言）+ 行首色点；
  颜色 FAV `#84cc16` lime / TOP `#3b82f6` blue / NEW `#a855f7` purple / REC `#14b8a6` teal /
  FREE `#94a3b8` slate（全冷色/中性，避开红黄警告色）；英文标签；web 走 i18n 词典。
- **托盘面板**：顶部 Favorites 卡（按 provider 列心选 chip + 空位「+」）；点 chip / + 打开
  **provider 维度比较选择器**（该 provider 目录全量，列：昨日 token / 失败率 / ttft / 价位，
  带搜索，点击行即换选心选）。选择器必须用目录全量——Models 用量列表不含无流量模型，
  不能作为选择来源（用户实证否决"列表打星"方案的原因）。
- **引导横幅**：全局被动（"No favorites picked — running on auto defaults (TOP/NEW)"），
  任一心选存在即隐藏；点 Choose 打开第一个有空位 provider 的选择器。
- **Web dashboard**：模型行同款来源标签 + 每 provider 收藏编辑卡（同列对比）+ 同 API
  （双入口同源，同 priority ▲▼ 模式）。

## 方案取舍（已裁决）

| 备选 | 裁决 | 原因 |
|---|---|---|
| 硬分流（掷骰 70/10/20 或配额控制器） | 否决 | 用户明确要打分涌现、不要硬限制；掷骰致相邻请求跳变 |
| 托盘 Models 列表打星 | 否决 | 列表按用量排名，无流量模型不可见，无法选 |
| 实心色块 / 色条标签 | 否决 | 用户选定淡底描边（与现有胶囊同语言） |
| 保留带距 100 碾压 | 否决 | 正档位豁免质量下限 + 碾压 → "默认 higher 的免费"在难题也必胜，违背用户难题意愿 |
| 份额反馈控制器 | 否决 | 用户：打分涌现即可，不要反馈式硬拉 |
| 心选默认 +1 作为完整档位 | 否决 | 设心选即打断全部粘性会话；改为仅总分 ×1.30 软偏好（显式 ▲▼ 才有强语义） |
| 保留 enable/disable 开关 | 否决 | 与 Off/Pinned/心选语义重复、无名额可"顶"；整套退役下线 |
| 带距改造只用心选路 | 否决 | 两套平行档位语义、▲▼ 双模式行为不一致；用户裁决两路共用 |
| 心选范围直接替换组合算法 | 演进为双路径 | 用户提出"网关智能 / 心选智能"两条路径都保留，开关动态切换 |

## 留给实现者的决定

- 选择器在窄面板中的呈现形式（popover 二级页 vs 卡片内展开）。
- NEW 衰减参数（50K token 起点）与"来源分布"的观察窗口长度。
- 粘性与份额的相互作用（份额只在新决策点移动；粘性语义不变）。
- provider 降级/配额闸时的范围替补（沿用现有 sweep/兜底，范围层不重复处理）。
- i18n 文案与本地化 key 命名。
